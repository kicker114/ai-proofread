## proofread max 卡死根因（重要，可复用）
- 现象：后台任务 `0cQC9N` 跑 `proofread max review_prose.md --concurrent 3 --rpm 15 --chunk-size 200`，44 分钟仍 running，仅 chunk-000002 完成（status=complete），无任何 failed checkpoint。
- 根因：`src/proofreader.py` 里 OpenAI client 用 `timeout=API_TIMEOUT_SECONDS(=300)` + `max_retries=0`；DeepSeek 在高负载下"收下请求但不吐响应/极慢吐"，httpx 的 read timeout 按"距上次收字节"计时，被慢速 trickle 持续重置 → 300s 不触发。请求跑在 ThreadPoolExecutor 线程里，`phase1_json_proofread` 用 `asyncio.gather` 等全部 chunk，单 chunk 卡死则整段 Phase 1 永久阻塞。无 `asyncio.wait_for` 看门狗。
- 环境：`proofread` 实际跑在系统 python3.14（/usr/local/opt/python@3.14），openai 2.37.0 / httpx 0.28.1。
- 命令里的 `| tail -40` 还会把全部进度 print 缓冲到 EOF，进一步掩盖卡死。
- 修复方向：在 worker/chunk 层加 `asyncio.wait_for(..., timeout=N)`（事件循环时钟，必触发），并加整体 Phase 1 预算；降低单请求 timeout 或显式 connect/read 超时；去掉 `| tail -40` 或改写日志文件。
- 结论：关键路径不要依赖 DeepSeek 管线，试点改用子 agent + 人工对照原文核验，更稳。
